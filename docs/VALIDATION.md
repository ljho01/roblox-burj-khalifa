# 검증 기록

2026-09-26, macOS에 설치된 Roblox Studio와 Rojo 7.7.0으로 확인했습니다.

## 숫자 슬롯과 빼돌리기 방어

- 고정 슬롯 1 자재 / 2 뺨때리기 / 3 빠따 / 4 바나나를 추가했습니다. 숫자 키와 클릭·터치가 같은 장착 경로를 사용합니다. 자재 선택은 무기를 해제하며 등 위 운반물은 유지합니다. 기본 Backpack UI를 숨겨 번호가 충돌하지 않게 했습니다.
- 실제 Studio 2인 검사에서 숫자 키 바인딩을 조회하고 동일 입력 콜백으로 슬롯 전환을 실행했습니다. 14개 자재를 멘 상태로 모든 슬롯을 반복 전환하고 서버 장착 결과·클라이언트 선택 표시·사용권 미소모·행동 버튼과 슬롯 비겹침을 확인했습니다. OS 키보드 이벤트를 합성한 검사는 아닙니다.
- 빈 2번 슬롯을 눌러 해당 뺨때리기 상품 흐름만 요청하고, 지급 전에는 자동 장착되지 않는 것을 확인했습니다. Studio에서는 실제 Robux 결제창 대신 기존 무료 체험 서버 경로로 지급을 검증했습니다. 라이브 코드는 2/3/4번을 각각 카탈로그의 뺨때리기/빠따/바나나 Developer Product ID로 `PromptProductPurchase`에 전달합니다. 실제 Robux 결제는 수행하지 않았습니다.
- 상대 클라이언트가 기본 프롬프트로 빼돌리기를 시작한 뒤, 방어자 클라이언트의 2번 슬롯 선택 → 실제 Tool 활성화 → 서버 명중 판정으로 즉시 취소됐습니다. 원래 누르기 시간이 지난 뒤에도 자재가 지급되지 않고, 건설량 30개와 예약 해제가 유지되는 것을 확인했습니다.
- 이미 챙긴 분홍 자재도 3번 빠따 장착·공격으로 회수됐습니다. 두 명중은 각각 해당 사용권 하나만 소모했습니다. 공격자에게 방어 성공, 상대에게 빼돌리기 취소 알림을 추가했습니다.
- `./scripts/test.sh --sabotage` 통과. 로그: `tests/results/hotbar-purchase-multiplayer.log`, `BURJ_HOTBAR_PASSED`, `BURJ_THEFT_DEFENSE_PASSED`, `BURJ_TEST_RESULT true nil`. 실물 모바일 터치와 온라인 게시 검사는 포함하지 않았습니다.
- 기존 `./scripts/test.sh --multi`도 통과했습니다. 로그: `tests/results/hotbar-purchase-regression.log`. 최종 빌드의 24개 실행 스크립트가 프로젝트 소스와 일치하고 테스트 코드가 없는 것을 확인했습니다.
- 최종 로컬 파일을 다시 빌드해 Studio로 열었습니다. 하단 1~4번 슬롯과 행동 패널의 간격은 앞선 플레이 화면에서 확인했고, 이번 구매 문구와 상품 연결은 소스 일치 검사 및 2인 Studio 테스트로 확인했습니다. 실제 Robux 결제창과 온라인 게시는 확인하지 않았습니다.

## E 길게 누르기와 자재 수량별 로그 시간

- 빼돌리기를 기본 ProximityPrompt의 E 길게 누르기로 변경했습니다. 누르기가 완료되면 즉시 자재를 받으며, 별도 대기 단계는 없습니다. HUD 버튼의 마우스·터치와 게임패드에도 같은 입력을 연결했습니다.
- 시간은 `2.2 × ln(1 + 실제 예약 수량) / ln(9)`초입니다. 8개 2.2초, 32개 약 3.5초, 128개 약 4.9초입니다. 서버가 실제로 예약한 수량으로 계산하고 경과 시간·거리·이동·피격·라운드를 검증합니다.
- `./scripts/test.sh --sabotage`: 실제 Studio 서버와 클라이언트 2개에서 기본 프롬프트의 누르기 시작/종료를 실행해 통과했습니다. 완료 직후 자재 지급, 0.45초 만에 손을 뗐을 때 취소 및 이후 미지급, 중간 이동·피격·사망 취소를 확인했습니다. 시작 요청만 보내고 시간이 지나도 자동 지급되지 않습니다.
- 동시 시도에서 첫 플레이어가 8개를 예약한 뒤 두 번째 플레이어는 남은 22개만 예약했습니다. 표시·프롬프트 시간을 약 3.139초로 다시 맞췄고, 해당 마감 시각 약 0.043초 뒤에 지급됐습니다. 가방 최대 용량이나 처음 보인 30개로 기다리지 않습니다.
- 기존 8/14/128개 운반, 쓰레기통에서만 건설 차감, 중복 요청·완공·라운드 초기화, 1,000회 예약/폐기 교차 실행, 층·크레인 감소도 함께 통과했습니다. 로그: `tests/results/log-hold-multiplayer.log`, `BURJ_TEST_RESULT true nil`.
- `./scripts/test.sh --multi` 기존 회귀 검사도 통과했습니다. 장난감 3종의 자재 낙하, 공동 건설, 플레이어별 친구 운반자 1명과 업그레이드, 완공을 확인했습니다. 로그: `tests/results/log-hold-regression.log`, `BURJ_TEST_RESULT true nil`.
- `dist/Build-the-Burj.rbxlx`의 23개 스크립트가 프로젝트 소스와 일치하고 테스트용 스크립트가 포함되지 않았음을 확인했습니다.
- 아래의 기존 고정 2.2초 빼돌리기 기록은 이전 구현입니다. 이번 구현이 이를 대체합니다. 실물 터치 기기·콘솔 및 온라인 게시는 이번 검사에 포함하지 않았습니다.

## 자재 빼돌리기와 쓰레기통

- `./scripts/test.sh --sabotage`: 실제 Studio 서버 + 클라이언트 2개 통과. 두 클라이언트의 RemoteEvent로 8개·14개 동시 빼돌리기 및 쓰레기통 버리기를 실행했습니다.

## 친구 아바타 작업자

실제 Studio 단독 플레이에서 로그인 계정의 친구 47명을 API로 읽고, 선택된 친구의 실제 아바타 생성과 기본 작업자 교체를 확인했습니다. 클라이언트에서 80스터드 이상 이동, 팔 관절 움직임, 자재를 메고 이동한 뒤 내려놓고 돌아오는 동작을 검증했습니다. 친구 이름은 표시하지 않고 기본 Humanoid 이름표도 숨깁니다.

- 친구 목록 페이지 순회와 중복 제거, 랜덤으로 섞은 목록을 한 바퀴 돌기 전 중복 고용 방지
- 자재를 내려놓을 때만 서버 보상, 같은 도착 시점 중복 지급 방지
- 완공 중 휴식과 다음 라운드 작업 재개, 접속 종료 때 작업자 제거
- 친구 없음·API 실패 시 기본 작업자 유지, 떠난 뒤 늦게 도착한 아바타 제거
- 실제 클라이언트 2개에서 각 작업자의 왕복 동작과 다른 플레이어 작업자 표시
- 각 플레이어에게 자재 2개·6코인씩 반영되고 기존 공동 완공 보상이 정상 동작

로그: `tests/results/friend-workers-solo.log` (`BURJ_WORKER_ROSTER Ready 47 Friend`, `BURJ_TEST_RESULT true nil`), `tests/results/friend-workers-multiplayer.log` (`BURJ_WORKERS_MULTIPLAYER_PASSED 2`, `BURJ_TEST_RESULT true nil`). 테스트 친구 목록 모형은 별도 테스트 파일에만 있으며 배포 파일에 포함되지 않습니다.
